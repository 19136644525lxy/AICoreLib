# 附属模组方案：Monsterheart
### 中文名：我跟AI怪物在MC谈恋爱（已定稿保留）

> 类型：AICoreLib 的内容型附属模组（Addon）
> 目标版本：MC 1.21.1 / Fabric + NeoForge
> 状态：方案文档，未写代码。**开发顺序：主库完工后再开工。**
> 前置依赖：AICoreLib（必须）；客户端（可选）

---

## 0. 一句话定位

把 galgame 的「攻略—好感—事件—结局」骨架，套在 AICoreLib 已经能驱动的**任意生物**身上：
**你注入的每一只生物，都可以选择开不开启恋爱路线。开启的，就是一条个人线。**

**两条重要前提（勿混淆）：**

1. **恋爱不是生物类型自带的属性，而是玩家手动打开的开关**（见 §4.0）。苦力怕可以是纯战斗伙伴，牛也可以是恋人，全看玩家开不开。
2. **任何 `Mob` 都可以**：敌对、中立、友好、水生、飞行都走同一套系统。**友好生物不是特例** —— 牛、猪、羊、村民、狼、马、猫都行。这一点直接依赖主库「A 档 = 全部 Mob」的实体范围。

## 1. 命名（已定）

### 1.1 英文名
**`Monsterheart`**
- 完整写法：`AICoreLib: Monsterheart`
- modid：`monsterheart`
- 理由：`Monster` 点题、`heart` 点题恋爱；单词造词，搜索唯一性高；短，适合做系列前缀。

| 候选 | 评价 |

| `Love & Loot` | 押韵好记，但过于泛化，且没有"怪物"和"AI" |

## 2. 调研：galgame 的机制内核

### 2.1 标准骨架
```
序章 / 共通线 ──→ 角色登场 ──→ 日常事件 ×N ──→ 分歧点 ──→ 个人线 ──→ 结局
```

| 段落 | 作用 | 在 MC 里的对应 |
|---|---|---|
| 共通线 | 所有角色都在，建立印象，不锁人 | 世界里所有开启恋爱路线的 agent 都能互动 |
| 分歧点 | 一个关键选择 + 好感门槛，决定走谁的线 | "确认关系"事件：对某只生物表白 |
| 个人线 | 只有该角色的事件，好感继续涨 | 该 agent 专属事件链 |
| 结局 | True / Good / Normal / Bad / 婚后 | 见 §4.9 |

### 2.2 五个可以移植的机制内核

1. **数值分段，不是线性** —— 好感度涨到某一段就停滞，必须有事件推动。
2. **上限锁（最关键）** —— 好感到 39 卡死，需触发「第一次并肩作战」；到 59 卡死，需要「送她一件能保命的东西」；到 79 卡死，需要「表白事件」。**没有这个锁，玩法会在两天内被刷穿。**
3. **事件驱动而非随机** —— `条件满足 → 触发`，不是概率。
4. **路线锁定** —— 确认关系后，其他角色的个人事件不再推进（但不会翻脸，只是停住）。
5. **回想 / 图鉴** —— 已解锁内容可回看，制造收集欲。

### 2.3 不能直接搬的部分，以及替代方案

| galgame 元素 | 为什么不能搬 | MC 替代方案 |
|---|---|---|
| 立绘 + 表情差分 | 3D 实体没有 2D 立绘 | 实体本体（可缩放/染色）+ 对话框左侧 64×64 头像（6 种表情差分） |
| 背景 CG | 没有 CG 概念 | 场景截图 → 存成「地图画」或「画」挂在墙上当收藏 |
| 点击推进文本 | 聊天栏是异步的 | 一段话 = 一条消息 + 可点击的 `[继续]`；重要对话进「回忆录」成书 |
| 多存档槽 | MC 只有一个世界存档 | 关系快照存 `SavedData`，提供 `/monsterheart snapshot` 导出 |
| BGM / 语音 | 没有 | 原版音效 + 音符盒 / 唱片机；可选资源包 |
| 快进已读 | 意义不大 | 不做 |

### 2.4 已有先例（值得借鉴，不必重复踩坑）

- [Touhou Little Maid](https://github.com/TartaricAcid/TouhouLittleMaid)（东方小女仆）：用「分级好感度 + 礼物 + 日常互动 + 任务」把恋爱养成做成 MC 里最成熟的形态，证明"宠物 + 好感度"完全成立。
- [Touhou-Maid-Affection](https://github.com/yabo083/Touhou-Maid-Affection)：NeoForge 1.21.1 的互动附属模组（亲吻、心形粒子、好感加成），证明 1.21.1 上这条路线可行，且**社区确实会为"多一点点亲密互动"单独做附属模组**。
- [Girlfriends](https://github.com/Viola-Siemens/Girlfriends)：带好感度系统的 MC 恋爱模组。

**结论**：这条路有人走过，但没人做过「任意生物 + AI 驱动 + 完整 galgame 结构 + 开关式开启」这一组合。差异化就在这里。

## 3. 为什么是附属模组，不是主模组功能

| 维度 | 判断 |
|---|---|
| 定位纯度 | AICoreLib 是库，恋爱是内容。库不该内置具体玩法 |
| 依赖方向 | 附属 → 主模组，单向。主模组永远不知道 Monsterheart 存在 |
| 更新节奏 | 恋爱内容要频繁加角色/加事件，不该拖着主模组发版 |
| 玩家选择 | 只想要 AI 行为的玩家不必装恋爱内容 |
| 风险隔离 | 恋爱/分级相关的争议不污染主模组 |

**纪律**：Monsterheart 只能通过 AICoreLib 的公开 API 工作，不许反射、不许 mixin 进主模组内部类。

## 4. 核心系统设计

### 4.0 恋爱路线是「开关」，不是生物模板

这是本模组与所有"女仆/恋爱模组"最根本的区别：**没有恋爱专用的生物，任何被注入的生物都可以被打开恋爱路线。**

| 项 | 设计 |
|---|---|
| 出现条件 | 仅当服务端装了 Monsterheart 时，客户端面板/交互里才出现 `[开启恋爱路线]`。没装的服，这个按钮和整套关系数据**完全不存在**（不是隐藏，是不注册） |
| 默认值 | **关闭**。关闭时该 agent 只是普通 AI，不产生任何关系数据，行为完全走主库预设 |
| 打开后 | 写入 relationship 数据（存 `AgentState.extras`）、加载该生物的对话包与事件链、开始计算好感/信任/恐惧 |
| 关闭 | 关系**冻结**不删除；重新打开时从冻结处继续 |
| 适用范围 | 任意 `Mob`：敌对（僵尸/骷髅/苦力怕）、中立（末影人/猪灵/蜘蛛）、友好（牛/猪/羊/村民/狼/马/猫）、水生（鱿鱼/海豚）、飞行（蜜蜂/鹦鹉/幻翼） |
| 多人生存 | 一个生物同一时间只能有一个恋人；关系绑定玩家 UUID，换人需先解除 |
| 权限 | 默认由注入者（主人）开启；服务器可配置为仅 OP 可开 |

**"友好生物"为什么重要**：牛、猪、村民这些没有战斗能力，但它们是"陪伴型"路线的最佳载体 —— 不用陪你打怪，只要在农场等你回家。这反而更接近 galgame 的核心体验。系统必须一视同仁，而不是把它们当彩蛋。

### 4.1 关系数值模型（三条轴）

| 数值 | 范围 | 初始 | 作用 |
|---|---|---|---|
| **好感 Affection** | 0–100 | 0 | 主进度条，决定事件解锁与结局 |
| **信任 Trust** | 0–100 | 10 | 决定她是否听指挥、是否允许你靠近/骑乘、战斗中会不会误伤你 |
| **恐惧 Fear** | 0–100 | 敌对生物 80 / 友好生物 10 | **生物特有**。>50 时会逃跑或攻击你；靠喂食、不主动攻击、共同战斗下降 |

三者分开的理由：
- 只有好感 → 玩家会觉得"送礼物就能攻略"，没有风险感。
- 加上恐惧 → 保留"她是个怪物"的张力。**你先得让她不怕你，才谈得上别的。**（友好生物初始恐惧低，但"信任"仍需慢慢建立，否则她不会跟你走。）
- 加上信任 → 战斗与生活两条线分开，能设计"她替你挡刀"这种事件。

### 4.2 阶段与上限锁

```
敌对(0) → 警惕(10) → 好奇(25) → 亲近(40) → 依恋(60) → 恋人(80) → 挚爱(100) → 结婚
```

| 卡点 | 门槛 | 解锁条件（必须触发事件，光刷数值无效） |
|---|---|---|
| 卡在 39 | 亲近 → 依恋 | 「第一次并肩作战」：共同击杀一只敌对生物，且她存活（友好生物改为「第一次同行」：带她离开出生点 200 格并平安返回） |
| 卡在 59 | 依恋 → 恋人 | 「保命之物」：送她一件能防止白天燃烧的装备并亲手戴上（友好生物改为「一件信物」：任意被她喜欢的物品，命名后赠送） |
| 卡在 79 | 恋人 → 挚爱 | 「表白」：在她的"喜欢的地方"触发表白事件 |
| 100 | 挚爱 | 完成全部 5 个个人事件 |
| 结婚 | 挚爱之上 | 「求婚」：好感 100 + 信任 ≥ 80 + 信物（玩家用铁砧命名的物品）+ 婚礼事件（她的喜欢地点、无战斗、双方在场） |

**为什么第一个锁是"共同战斗"**：它把恋爱和 MC 的核心玩法绑在一起，而不是逼玩家刷礼物。友好生物用"同行"替代，逻辑一致。

### 4.3 对话系统（双层，这是与主模组的分界点）

| 层 | 内容 | 何时用 |
|---|---|---|
| **台词库** | 数据包 JSON，每角色每阶段 30~50 句，带条件标签 | 默认；**没有 API key 也能完整通关** |
| **LLM 层** | 通过 AICoreLib 的 `LlmProvider` 生成，带角色人格 prompt | 玩家配置了 key 且开启时叠加，用于自由对话 |

**硬性要求**：离线必须可玩。LLM 是"锦上添花"，不是"能不能玩"的前提。

对话触发方式：
- 右键她 → 打开对话（当前阶段随机台词 + 事件台词）
- 聊天栏 `@她的名字 内容` → 走 LLM 自由对话（可选）
- 距离近 + 长时间未互动 → 主动走过来低频率说一句（避免刷屏）

### 4.4 事件系统（数据包驱动）

```json
{
  "id": "monsterheart:creeper/first_explosion",
  "character": "minecraft:creeper",
  "stage": [40, 59],
  "conditions": {
    "affection_min": 45,
    "time": "night",
    "weather": "clear",
    "biome": "#minecraft:is_forest",
    "requires": ["monsterheart:creeper/first_gift"]
  },
  "once": true,
  "dialogue": [
    { "speaker": "creeper", "text": "……我差点又炸了。", "emotion": "scared" },
    { "speaker": "player", "text": "没关系，我在这儿。" }
  ],
  "effects": { "affection": 8, "trust": 5, "fear": -10 },
  "unlock": ["monsterheart:creeper/route"]
}
```

条件字段：好感区间、信任、恐惧、时间、天气、生物群系、结构、距离、手持物品、前置事件、是否已确认关系。

### 4.5 礼物偏好表（MC 味的笑点）

| 生物 | 喜欢（+好感） | 讨厌（-好感） | 梗 |
|---|---|---|---|
| 苦力怕 | 火药 +3、猫 +5 | 猫 -8（但猫同时能阻止她爆炸） | 送猫是自杀式浪漫 |
| 骷髅 | 骨头 +2、箭 +2 | 盾牌 -5 | 她射你，你举盾 |
| 末影人 | 末影珍珠 +4 | 水桶 -10（淋湿会传送逃走） | 别在她面前放水 |
| 僵尸 | 腐肉 +1、熟肉 +3、金苹果 +6 | 治疗药水 -5（会受伤） | 治愈药水是毒药 |
| 蜘蛛 | 蜘蛛眼 +2、线 +1 | — | — |
| 女巫 | 红石 +2、糖 +2 | 牛奶 -8（会解掉她的药水） | — |
| 猪灵 | 金锭 +3 | 下界合金 -20 | — |
| 村民 | 绿宝石 +4、面包 +2 | 僵尸 -30 | — |
| 牛 / 猪 / 羊 | 小麦 / 胡萝卜 / 小麦 +3 | — | 喂食即日常 |
| 狼 / 猫 | 骨头 / 生鱼 +4 | — | 驯服过的直接 +10 |
| 马 | 金苹果 +5、干草块 +3 | — | — |
| 蜜蜂 | 任意花 +4 | — | 送花会引来蜂群 |

**通用**：送花 +2，送蛋糕 +5（放下就被吃，要重做）。
**每日上限**：好感每天最多 +10，防止一箱金苹果一夜通关。礼物边际递减（同类礼物每天 3 次后收益减半）。

### 4.6 约会与场景

- **地点偏好**：每个角色 2~3 个"喜欢的地方"（生物群系 / 结构 / 高度）。
  - 苦力怕：森林、洞穴
  - 骷髅：沙漠、雪原（干燥、开阔）
  - 末影人：末地、蘑菇岛、夜晚的平原
  - 牛 / 羊：草原、花海
- **白天限定的难题（本模组最好的机制之一）**：敌对生物白天会被烧死。想白天约会，必须先给她头盔/盔甲。**装备 = 爱的证明**，比任何台词都直观。友好生物没有这个限制，但"带她出门"本身需要信任值达标。
- **雷雨天特例**：雷雨天白天不燃烧 —— "雷雨天约会"成为稀缺、有仪式感的窗口。天气系统直接变成约会资源。
- **约会结算**：到达地点 + 停留 ≥ 60 秒 + 无战斗 → 好感 +5~10，解锁专属台词。

### 4.7 回忆录（成书系统）

每次重要事件结束，自动生成/追加一页到成书「她的回忆录」，放进玩家背包（已有则追加）。
- 内容：事件名、游戏内天数、一句她的台词。
- 作用：替代 galgame 的「回想模式」，同时是可炫耀的实物收藏。
- 婚后自动改名为「我们的回忆录」。

### 4.8 修罗场（MC 独有的玩法）

当玩家同时与 ≥3 个角色进入「恋人」阶段：
- 触发「修罗场」：她们会互相看见。
- 结果取决于信任值与选择：和平共处 / 争吵 / 其中一个离开（回退到"亲近"）。
- **已婚状态下判定更严**：被发现出轨，配偶好感 -40，且当天不可挽回。

### 4.9 结局

| 结局 | 条件 |
|---|---|
| **True End** | 好感 100 + 5 个个人事件全完成 + 她未死亡 |
| **婚后（在 True End 之上）** | 完成求婚与婚礼，进入"同居"状态：可切换跟随/待命、每日特殊互动、解锁婚后台词 |
| **Good End** | 好感 ≥ 80 + 至少 4 个个人事件 |
| **Normal End** | 好感 40~79 |
| **Bad End** | 好感 < 25，或你亲手杀了她 |
| **失忆 End（隐藏）** | 她死过，你用 AI 核心复活了她，且没能在 3 次内补回记忆 |
| **不灭 End（隐藏）** | 复活 3 次以上仍然回到 100 好感 —— 记忆碎了，但她还是记得你 |

**离婚**：可主动解除婚约，好感 -30 且不可逆（可重新攻略，但不能恢复原数值）。

### 4.10 死亡 = 失忆：把主库的核心系统变成叙事

| 主库机制 | Monsterheart 里的意义 |
|---|---|
| 死亡掉 AI 核心 | 她的"心脏"掉了 |
| 核心右键新实体 | 转生 / 换了一具躯体（可以是同种，也可以是别的生物 —— 换种族是可选开关） |
| 记忆只保留 60%、好感 -20% | **失忆**：她还记得喜欢你，但忘了为什么 |
| 迁移 3 次上限 | 三次之后核心损坏 → 永久失去她 |

**这条机制不要额外发明，直接用主库的**。它是整个附属模组最动人的部分：玩家会为了保护她而战，而不是为了刷数值。

## 5. 与 AICoreLib 的依赖边界

Monsterheart 需要的、主库**必须提供**的 API（反推回主库设计，已写入 DESIGN.md §18）：

| 需求 | 用到的主库扩展点 | 状态 |
|---|---|---|
| 给 agent 挂自定义数据（relationship） | `AgentState.extras`（`Map<ResourceLocation, byte[]>`） | ❌ 需补 |
| 玩法开关（恋爱开关） | `AgentState.flags` 或 extras 内的布尔位 | ❌ 需补 |
| 感知/生命周期钩子 | `AgentListener`（injected / removed / tick / death） | ✅ 计划中 |
| 自定义动作（kiss / gift / date / follow） | `AiAction` 注册 | ✅ 计划中 |
| 影响提示词（人格、关系状态） | `PromptContributor` | ✅ 计划中 |
| 禁止她攻击主人 | `SafetyPolicy` | ✅ 计划中 |
| 对话走 LLM | `LlmProvider` + 异步调度 | ✅ 计划中 |
| 客户端面板加一页 | `AgentPanelTab` | ⚠️ 主库要暴露注册入口 |
| 自定义界面（对话框） | 网络包 + 客户端 Screen | ⚠️ 主库要暴露注册入口 |

**结论**：M0/M1 必须先把 `AgentState.extras`、`AgentState.flags`、`AgentListener` 做出来，否则附属模组只能自建存档，导致状态分裂。

## 6. 内容规模

| 内容 | 数量 | 备注 |
|---|---|---|
| 首发可攻略角色 | **3 个**（苦力怕 / 骷髅 / 末影人）+ 1 个友好生物样板（牛） | 机制差异大；友好生物样板用来证明"非战斗路线"也能成立 |
| 每个角色的个人事件 | 5 个 | 对应 4.2 的锁 + 1 个结局前置 |
| 每个角色台词 | 120~180 句 | 分阶段，写作量最大的一块 |
| 表情差分头像 | 每角色 6 张（64×64） | 平静/害羞/生气/害怕/开心/难过 |
| 结局 | 7 个（含婚后） | 见 4.9 |
| 礼物偏好条目 | ~60 | 覆盖常见生物 |

**注意**：3 个角色只是**首发样板**，系统本身对任意 `Mob` 通用 —— 加一个新角色是纯数据增量（一个 JSON + 一套台词 + 头像），不碰代码。这是"开关式"设计的直接收益。

## 7. 里程碑（主库完工后启动）

| 阶段 | 内容 | 验收 |
|---|---|---|
| G0 数值骨架 | 好感/信任/恐惧、阶段、上限锁、礼物、每日上限、恋爱开关 | 能开/关恋爱路线，送礼与共战把好感推到 39 并卡住 |
| G1 事件系统 | JSON 事件加载、条件判定、对话播放（聊天栏 + 可点击选项） | 加个 JSON 就能触发一段剧情 |
| G2 三加一角色 | 3 条敌对线 + 1 条友好生物线、头像、场景偏好、白天燃烧难题 | 能完整攻略一条线到 Good End |
| G3 对话与情感 | LLM 自由对话、情绪差分、回忆录成书 | 配 key 后能自由聊天并写进回忆录 |
| G4 结局与婚后 | 7 个结局、修罗场、失忆链、求婚/婚礼/婚后同居 | 全结局可达 |

## 8. 风险

| 风险 | 对策 |
|---|---|
| **内容量爆炸**（文本是代码的 10 倍） | 先做 3+1 验证；台词模板化；社区投稿接口 |
| LLM 生成不当内容 | 全年龄硬约束 + prompt 强约束 + 输出过滤 + 默认关闭 |
| 分级与平台政策 | 明确标注「全年龄，无 NSFW」；Modrinth 对 NSFW 有政策限制 |
| 与主库耦合失真 | 只走公开 API；主库 CI 加"附属模组能否编译"检查 |
| 玩家把生物当工具人 | 恐惧值 + 死亡失忆的代价 |
| 多人服务器抢老婆 | 一个生物一个恋人；关系绑 UUID；已婚出轨重罚 |
| 刷好感 | 每日上限 + 上限锁 + 礼物边际递减 |
| 开关被滥用（给全地图生物开恋爱） | 每玩家上限（默认 3 个恋爱对象） |

| 1 | 中文名 | **保留全句**「我跟AI怪物在MC谈恋爱」 |
